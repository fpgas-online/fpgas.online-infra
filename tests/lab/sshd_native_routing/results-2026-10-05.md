### H-token. ForceCommand does not expand %u: PASS

ForceCommand takes no tokens: the relay cannot be told the name on its command line. It reads $USER, which sshd sets from the account it authenticated, after any client-supplied variables.

```

```

### T-landlock. Landlock alone (no ChrootDirectory): the relay sandboxes itself: PASS

Landlock needs no privilege, no setuid helper and no user namespace, and works from a ForceCommand as it is. The relay requires ABI 6 (trixie's kernel has it) and refuses to run without. ### T-bwrap. bubblewrap from an unprivileged process: PASS

bwrap on trixie is not setuid; it needs unprivileged user namespaces (Debian's default, kernel.unprivileged_userns_clone=1). Docker's default profiles forbid creating them, which is a property of the lab container and not of a trixie host: with them lifted it works. A process inside a chroot may not create a user namespace at all (user_namespaces(7)), so bwrap and sshd's ChrootDirectory cannot be combined: it is one or the other.

```
table inet fpgas_board_relay {
    set boards {
        type ipv4_addr
        flags interval
        elements = { 10.121.1.1-10.121.1.48, 10.121.2.1-10.121.2.48 }
    }
    set per_board {
        type ipv4_addr
        flags dynamic
    }
    chain output {
        type filter hook output priority filter; policy accept;
        # Positive match only. "meta skuid != 950 accept" would be wrong:
        # a packet with no socket (neighbour discovery, a kernel reset) has
        # no uid, matches neither form, and would fall through to the reject.
        meta skuid 950 jump board_relay
    }
    chain board_relay {
        ct state established,related accept
        ip daddr @boards tcp dport 22 ct state new add @per_board { ip daddr ct count over 8 } counter reject with tcp reset
        ip daddr @boards tcp dport 22 ct state new counter accept
        counter reject with icmpx admin-prohibited
    }
}
```
